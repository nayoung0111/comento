# 4차 과제 — 악보 마디 인식 (규칙기반 → 딥러닝)

## 프로젝트 설명

악보 이미지에서 마디(measure)를 자동으로 인식하는 기능을 규칙 기반(OpenCV)과 딥러닝(YOLOv8) 두 가지 방식으로 시도하고 비교한 프로젝트입니다.

## 진행 과정 요약

### 1차 시도 — 규칙 기반(OpenCV) 마디선 감지

* 오선(악보 5줄) 위치는 정확히 자동 감지하는 데 성공
* 하지만 음표 기둥(stem)과 마디선의 굵기·높이가 비슷해, 실제 리드시트(코드+가사 포함)에서는 오탐지가 심함 (마디 4개짜리 구간에서 20개 넘게 잡힘)
* `sheet\_sample\_01\_detected...` 파일이 이 시도의 결과물로, 박스가 과도하게 많이 잡힌 것을 확인할 수 있음
* **결론**: 이 문제는 OMR(광학 악보 인식) 분야에서 전용 데이터셋과 딥러닝 모델이 따로 개발될 만큼 알려진 난제임을 확인하고, 딥러닝 방식으로 전환

### 2차 시도 — 딥러닝(YOLOv8) 기반 마디 탐지

* AudioLabs\_v2 데이터셋(940장, 클래식 악보 마디 주석 포함)을 YOLO 형식으로 변환해 Google Colab(GPU)에서 학습
* 검증(val) 데이터에서는 mAP50 0.995, mAP50-95 0.96의 높은 성능 달성
* 그러나 실제 테스트 이미지(리드시트)에 적용하자 학습 데이터(클래식 정악보)와의 스타일 차이(**도메인 갭**)로 인해 탐지 개수가 실제보다 적게 나오는 현상 발견 (기본 신뢰도 기준 0.25에서 5개, 12개만 탐지)

### 3차 시도 — 신뢰도(confidence) 파라미터 튜닝

* 신뢰도를 0.01\~0.05까지 낮춰가며 최적값 탐색
* `conf=0.015`에서 개수 기준으로는 실제 마디 수(약 18개, 28개)에 근접한 결과(20개, 23\~26개) 확보 → `sheet\_sample\_01\_final.jpg`, `sheet\_sample\_02\_final.jpg`가 이 최종 결과물
* **핵심 발견**: 개수는 목표에 근접했지만, 실제 결과 이미지를 열어보면 박스 여러 개가 서로 겹치거나 여러 마디를 한꺼번에 크게 감싸는 경우가 다수 발견됨. 즉 **"개수가 맞는 것"과 "위치가 정확한 것"은 별개**이며, 정량 지표(개수)만으로 성능을 판단하면 오해할 수 있음을 확인

## 파일 구조

|파일|역할|
|-|-|
|`measure\_detection\_dl.py`|학습된 YOLO 모델(`best.pt`)로 이미지에서 마디를 탐지하고 박스를 그리는 코드|
|`best.pt`|Google Colab에서 AudioLabs\_v2 데이터셋으로 학습한 YOLO 마디 탐지 모델|
|`sheet\_sample\_01.jpg`|원본 테스트 리드시트 이미지 (Toy Story 2 OST, 2페이지 중 1페이지)|
|`sheet\_sample\_01\_detected...`|1차 시도(규칙 기반) 결과 — 오탐지 과다 현상 확인용|
|`sheet\_sample\_01\_final.jpg`|최종(딥러닝, conf=0.015) 결과 — 1페이지|
|`sheet\_sample\_02\_final.jpg`|최종(딥러닝, conf=0.015) 결과 — 2페이지|

## Installation

```bash
python measure\_detection\_dl.py
```

(`detect\_measures` 호출 시 `conf=0.015`, `imgsz=1024`가 실제 마디 수에 가장 근접한 것으로 확인된 설정)

## 최종 성능 비교

|방식|score\_1 (목표 18개)|score\_2 (목표 28개)|
|-|-|-|
|규칙 기반|오탐지 과다 (20개 넘는 마디 구간에서 그 이상 잡힘)|오탐지 과다|

## 배운 점 및 향후 개선 방향

* 규칙 기반 CV는 빠르고 구현이 쉽지만, 시각적으로 유사한 요소(마디선 vs 음표기둥)를 구분하는 데는 한계가 명확함
* 딥러닝은 학습 데이터와 실제 적용 데이터의 스타일이 다르면(도메인 갭) 성능이 크게 떨어질 수 있음
* **"탐지 개수가 목표와 비슷하다"는 것이 "정확하게 탐지했다"는 뜻은 아님** — 신뢰도를 낮춰 개수를 맞추면, 그만큼 겹치거나 부정확한 박스도 함께 늘어날 수 있다는 트레이드오프를 확인함. 정량 지표(개수)만 보고 성능을 판단하면 오해할 수 있어, 실제 결과 이미지를 육안으로 확인하는 정성 평가가 함께 필요함
* 향후 개선 방향: 실제 리드시트 스타일 데이터를 일부 라벨링해 전이학습(fine-tuning) 진행, NMS IoU 임계값 조정 및 겹친 박스 후처리 로직 추가, 혹은 페이지별로 신뢰도를 동적으로 조정하는 로직 추가
